# Contributing

## Branches

Use focused branches named after the change, for example:

- `feat/signal-pipeline`
- `feat/fast-baseline`
- `feat/tiny-cnn`
- `test/reproducibility`
- `docs/github-showcase`

## Commit messages

Use imperative Conventional Commit-style messages:

```text
feat: add subject-level ECG windowing
fix: prevent normalization leakage across splits
test: cover label purity filtering
docs: document the experiment protocol
```

## Pull requests

Each pull request should explain the motivation, summarize the implementation, list validation
commands, and call out any limitations or follow-up work. Keep one conceptual change per PR.
